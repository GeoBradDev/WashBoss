# Plan: Dev toolchain npm audit advisories and Dependabot (issue #8)

Risk tier: Medium. Runtime dependencies (react, react-dom, MUI) move within their ranges and
ship to production on merge; rendering parity is only partly covered by the unit and axe
tests, so a live drive is required. No code path in the forced-High list changes: the diff is
`package.json`, `package-lock.json`, a new `.github/dependabot.yml`, and this plan.

Domain skills:
- vercel-react-best-practices: not applicable because no React source changes.
- frontend-design: not applicable because no UI changes.
- chrome-devtools-mcp:chrome-devtools (or claude-in-chrome): invoke for the live drive.
- run: invoke to launch `vite preview` for the live drive.

## Acceptance criteria

1. `npm audit` on a clean `npm ci` reports 0 high and 0 moderate vulnerabilities (and 0
   overall); `npm audit --omit=dev` still reports 0.
2. Every direct dependency stays within its existing semver range in `package.json` (no major
   change, no downgrade; eslint stays on 10.x). Ranges in `package.json` are raised only to the
   newly resolved minimum where needed, never across a major.
3. Any `overrides` entry targets one specific transitive package and is justified in the PR
   body.
4. `npm ci`, `npm run lint`, `npm test` (6 files, 43 tests) and `npm run build` pass.
5. The production preview renders the same as the pre-change build at 375px and 1280px:
   hero, gallery and lightbox (open, next/previous, close), mobile drawer (open, close),
   contact form rendering; no console errors. Bundle size reported before and after.
6. `.github/dependabot.yml` exists with `npm` and `github-actions` ecosystems on a weekly
   schedule, minor and patch updates grouped per ecosystem, no auto-merge.

## Order of work

1. `npm audit fix` (never `--force`), then `npm update`, then `npm audit`.
   Expected direct moves: vite 8.1.0 -> 8.3.6, @vitejs/plugin-react 6.0.3 -> 6.2.1,
   eslint 10.5.0 -> 10.14.0, globals 17.7.0 -> 17.14.0, eslint-plugin-react-refresh
   0.5.3 -> 0.5.7, react and react-dom 19.2.7 -> 19.3.1, @types/react 19.2.17 -> 19.3.0,
   @types/react-dom 19.2.3 -> 19.3.0, @mui/material 9.1.2 -> 9.5.0, @mui/icons-material
   9.1.1 -> 9.5.0. Transitive zod moves to 4.6.7.
2. The remaining finding after step 1 is `minimatch` (10.2.5 on main, 10.2.6 after
   `npm update`; GHSA-g3hv-75wg-m249, moderate, vulnerable `>=7.0.0 <11.0.1`), required as
   `^10.2.6` by eslint 10.14.0 and `^10.2.4` by @eslint/config-array 0.23.5. No patched
   10.x exists. Add `"overrides": { "minimatch": "11.0.4" }`, pinned exactly to the tested
   version so any later change to it is a deliberate edit (approved by the orchestrator;
   this is a major bump of a transitive package). Dependabot is not relied on to update
   or remove `overrides` entries, so the override is maintained by hand: the PR body says
   so, lists every package `npm ls minimatch` shows under it, and notes it can be removed once eslint and @eslint/config-array
   depend on a patched minimatch.
3. Raise the direct ranges in `package.json` to the resolved versions (same major), so a
   fresh resolve cannot fall back to vulnerable vite.
4. Add `.github/dependabot.yml`.
5. Gate, audit (full and `--omit=dev`), bundle size, live drive vs. the pre-change build.
6. Commit: `chore(deps): update toolchain and runtime deps within ranges to clear npm audit`
   and `ci: add Dependabot for npm and GitHub Actions`.

## Risks

- react 19.3 and MUI 9.5 are minor bumps that ship to production. Mitigation: full test
  suite including axe checks, and a side-by-side live drive against the baseline build.
- minimatch 11 under eslint 10: a major the eslint packages do not declare. A trial run
  showed `eslint .` clean, a seeded error still reported, `dist` and `.claude/worktrees`
  ignores still honored, and `--print-config` working. Alternative would be eslint 9
  (a downgrade, ruled out) or leaving one moderate advisory open.
- minimatch 11.0.x is about a week old; 11.0.4 needs Node `20 || >=22`, matching the
  `.nvmrc` (22) and `engines`.
- Bundle size may change slightly with MUI 9.5; reported either way. Not addressing the
  chunk warning here (out of scope).
- Not done: no major bumps, no `npm audit fix --force`, no repo settings changes.
